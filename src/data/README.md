# Portfolio data

作品と技術スタックは、ページごとに重複して書かず、次の2ファイルで管理します。

- `technologies.ts`: 技術ID、表示名、カテゴリ
- `portfolio.ts`: 作品、研究テーマ、公開状態、リンク、論文、技術IDの紐づけ
- `repository-triage.ts`: 公開リポジトリの掲載・貢献紹介・除外の判定と根拠

PortfolioのTechnical Stackは、作品で実際に使われている技術だけをカテゴリ別に表示する。技術を選ぶと、同じ技術IDを持つ作品へ絞り込める。

## 作品を追加するとき

1. 新しい技術を使う場合は、先に `technologies.ts` に安定したIDを追加する。
2. `portfolio.ts` の `works` に1作品を追加する。`id` は重複させず、`technologies` には定義済みのIDだけを指定する。
3. `availability` でリポジトリ、デモ、配布ページの公開状態を別々に記録する。非公開リポジトリのURLは `links` に追加しない。
4. 論文の公開日は `YYYY-MM` または `YYYY-MM-DD` で記録し、著者・掲載先・公開されている論文ページのURLだけを `publications` に追加する。
5. `npm run build` を実行する。型チェックに加えて、重複した作品/技術ID・未定義の技術ID・無効なリンク・公開状態とリンクの不整合・不正な掲載年月を検出する。

ビルドで検証できない掲載内容の事実関係（公開日、著者、リンク先の公開範囲、タイトル）は、追加時にブラウザで一次情報と照合します。

制作期間は、本人が公開しているREADMEや実装コミットなどで確認できる範囲を年単位で記録します。リポジトリの作成日や最終push日を開始・終了日とはみなさず、正確な月が確認できない場合は月を掲載しません。終了時期を確認できない継続中の作品は `YYYY–` と表記します。

## 公開リポジトリの判定

公開リポジトリを確認した結果、完成作品として掲載するもの、fork元の成果物とは分けて本人の貢献だけをAboutに掲載するもの、学習用・旧版・空リポジトリなどのため除外するものを `repository-triage.ts` に記録します。除外したリポジトリも判定理由と一次情報へのリンクを残し、公開リポジトリの確認漏れと自作作品との誤認を防ぎます。
